## 软件简介

InfoTransfer 是一款基于 .NET 8 开发的数据转发服务软件，主要用于：

- 接收终端数据并转发至飞书
- 监控 GD 系列交易策略信号
- 盘中止损情况实时监测
- 定时推送数据到指定终端

### 系统要求

- Windows 10/11
- .NET 8 Runtime

## 快速开始

### 1. 启动服务

首次使用时，需要进行以下配置：

1. 点击「服务器配置」设置 API 服务器

3. 点击「消息源设置」添加数据来源

## 功能模块

### 服务器配置

设置软件自身的 API 服务器端口和认证信息。

| 配置项 | 说明 |
|--------|------|
| API端口 | 服务器监听端口，默认 5000 |
| API密钥 | 访问认证密钥 |
| 启用认证 | 是否需要密钥验证 |

### 飞书推送配置

配置飞书机器人和推送目标。

| 配置项 | 说明 |
|--------|------|
| App ID | 飞书应用标识 |
| App Secret | 飞书应用密钥 |
| 机器人名称 | 飞书机器人名称 |
| 测试推送 | 发送测试消息验证配置 |

### 消息源设置

管理数据来源，支持：

- **HTTP API**：从外部 API 获取数据
- **WebSocket**：实时接收数据流
- **数据库**：从数据库查询数据

消息源配置项：
- **终端ID**：标识数据终端
- **消息格式**：JSON/文本/自定义
- **处理脚本**：可选的数据预处理脚本

## GD策略监控

### 配置步骤

1. 点击「配置GD监控」打开配置窗口

2. **API配置**
   - API基础地址：交易系统 API 地址
   - API Token：认证密钥

3. **策略选择**
   - 勾选要监控的策略：GD15、GD20、GD25、GD30、GD35、GD40
   - 系统会自动判断共振（同向持仓）

4. **时间配置**
   - 日盘时间段：默认 09:00-15:00
   - 夜盘监控：可选择启用
   - 监控频率：固定时间点 或 间隔分钟

5. **触发条件**
   - realTimeStopPriceDiffRate > 阈值
   - remainingRisk <= 阈值

### 共振判断逻辑

当勾选多个策略时，低等级策略会自动与高等级策略比较：

| 策略 | 检查更高策略 |
|------|-------------|
| GD15 | GD20, GD25, GD30, GD35, GD40 |
| GD20 | GD25, GD30, GD35, GD40 |
| GD25 | GD30, GD35, GD40 |
| GD30 | GD35, GD40 |
| GD35 | GD40 |
| GD40 | 无 |

**示例**：勾选 GD15、GD35、GD40
- GD15 只检查 GD35、GD40 是否同向
- GD35 检查 GD40 是否同向
- GD40 不检查

### 推送方式

- **文本消息**：简洁的文字描述
- **图片消息**：带表格的可视化图表

## 盘中止损监测

### 功能说明

实时监测交易品种的止损情况，支持：

- 多终端同时监控
- 可配置扫描间隔（1-60分钟）
- 仅在监控时间段内执行
- 支持文字和图片两种推送形式

### 配置项

| 配置项 | 说明 |
|--------|------|
| 推送终端 | 选择接收通知的终端 |
| 扫描间隔 | 1-60分钟 |
| 发送形式 | 文字/图片/两者 |

### 防闪烁机制

为防止数据抖动导致频繁推送，系统内置防闪烁机制：

- 品种状态变化后 5 分钟内再次变化会被忽略
- 除非品种回到之前未监控的状态

### 历史数据

系统会保存上次推送的数据，用于：

- 与下次数据进行比对
- 只在数据真正发生变化时推送
- 避免重复推送相同内容

## 定时推送

### 创建定时任务

1. 点击主界面「定时推送」
2. 点击「添加任务」
3. 填写配置：
   - **任务名称**：显示名称
   - **消息源**：数据来源
   - **推送终端**：目标终端
   - **执行时间**：多个时间点用逗号分隔，如 `08:00,12:00,20:00`
   - **推送类型**：文字/图片

### 任务管理

- **启用/禁用**：勾选启用任务
- **修改**：选择任务后编辑
- **删除**：确认后删除任务
- **立即执行**：手动触发一次推送

## API接口

### 接收消息

```
POST /api/message
Content-Type: application/json
Authorization: Bearer <token>

{
  "terminalId": "terminal_001",
  "sourceId": "source_001",
  "messageType": "text",
  "content": "消息内容",
  "timestamp": "2024-01-01T10:00:00Z"

```

```
GET /api/status
Authorization: Bearer <token>

Response:
{
  "status": "running",
  "pendingCount": 0,
  "sentCount": 100,
  "failedCount": 2

```

```
  "apiPort": 5000,
  "enabledTerminals": ["terminal_001"],
  "monitoringStrategies": ["GD15", "GD20"]
}
```

## 常见问题

### Q1: 服务启动失败

**可能原因**：
- 端口被占用
- 配置文件损坏

**解决方法**：
1. 检查端口是否被其他程序占用
2. 删除 `appsettings.json` 重新配置

### Q2: 飞书推送失败

**可能原因**：
- App ID/Secret 配置错误
- 机器人未添加到群
- 网络连接问题

**解决方法**：
1. 验证飞书应用配置
2. 检查机器人权限
3. 测试网络连通性

### Q3: GD监控无数据

**可能原因**：
- API 地址配置错误
- Token 过期
- 策略数据为空

**解决方法**：
1. 点击「测试API连接」验证
2. 检查策略勾选是否正确
3. 查看运行日志排查问题

### Q4: 定时任务不执行

**可能原因**：
- 任务未启用
- 服务未启动
- 时间格式错误

**解决方法**：
1. 确认任务已启用
2. 检查服务状态
3. 验证时间格式（如 `08:00,12:00`）

### Q5: 历史数据比对不准确

**解决方法**：
1. 删除 `gd_history.json` 历史文件
2. 系统会自动重新创建
